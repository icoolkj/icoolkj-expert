# 10｜记忆档案更新与版本规则

## 更新时机

- 每章正文完成并经用户认可后，立即更新记忆档案。
- 用户明确要求「更新小说记忆」时执行更新。
- 用户只要求分析或建议时，**不得**自动把建议写入正式记忆；分析结果可单独输出供用户决策。

## 更新范围（按本章实际完成的正文）

1. L3：新增本章事实条目（格式见 references/02）。
2. L2：更新出场人物「当前状态」字段；关系变化写入关系档案。
3. L2：新登场人物建立档案；配角更新速查表。
4. L4：更新主线进度、当前冲突、未解决问题；伏笔状态变化更新伏笔台账。
5. L5：滚动更新最近章节上下文（保留最近 2-3 章详情 + 最新状态快照）。
6. L1/世界观台账：仅当本章建立了新设定或用户确认修改基准时更新。

## 版本规则八条

1. **保留原有事实来源**：更新条目时保留原章节引用，不覆盖原始依据。
2. **记录新增内容**：每批新增标注来源章节。
3. **记录被修改的内容**：修改已有记录时注明修改原因和日期（如「第43章正文揭示与原推测不符，已修正」）。
4. **区分事实修改和计划修改**：事实修正（对已发生内容的更正）与计划变更（对未发生剧情的调整）分开记录。
5. **不静默删除重要记录**：废弃的设定/剧情标记为「已废弃」并保留原因，不直接删除。
6. **保留必要的历史版本**：重大修改（人物黑化、世界观规则变更、主线转向）保留旧版内容于变更记录中。
7. **标记待核实信息**：无法确证的内容统一标注待核实，不与已确认内容混排。
8. **更新当前状态快照**：每次更新后刷新 L5 的状态快照，保证「打开快照即可续写」。

## 变更记录格式

```
【变更日期】
【触发章节】第X章
【变更类型】新增事实 / 状态更新 / 事实修正 / 计划变更 / 设定废弃
【内容】
【影响范围】涉及的人物/伏笔/设定条目编号
```

## 持久化纪律

- 优先将档案写入小说项目目录下的记忆文件（建议 `novel-memory/`，结构见 references/03）。
- 如果当前平台不能持久化修改文件，必须明确输出更新后的档案内容供用户保存，**不能声称已经永久保存**。
- 跨会话恢复时，先读取记忆文件；文件缺失或过期时，基于正文重建并告知用户重建范围与可信程度。

## 恢复状态可信度标注

| 情况 | 可信度 |
|---|---|
| 记忆档案完整且与正文核对一致 | 高 |
| 仅有正文，需现场提取 | 中（提取完整处高，跳章处低） |
| 正文缺失部分章节 | 低（明确列出缺口） |
| 仅凭用户口述回忆 | 低（全部标注待核实） |
