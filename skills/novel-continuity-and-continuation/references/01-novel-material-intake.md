# 01｜小说资料接入与前文检索

## 资料接入清单

接收小说项目时，逐一检查以下资料是否存在、完整和可用：

| 资料类型 | 用途 | 缺失时的处理 |
|---|---|---|
| 小说正文 / 已有章节 | 事实提取的唯一权威来源 | 没有正文则无法做事实恢复，明确告知用户 |
| 章节摘要 | 快速恢复宏观进度 | 缺失时从正文提取，标注为待核实 |
| 人物档案 | 人物状态与关系基线 | 缺失时从正文提取并新建 |
| 世界观资料 | 设定一致性检查基线 | 缺失时从正文归纳已建立规则 |
| 故事大纲 | 了解计划剧情 | 仅作为计划，不当作已发生事实 |
| 历史修改记录 | 判断设定是否已废弃 | 缺失时以最新正文为准 |
| 已有创作记忆 | 直接恢复上次工作状态 | 缺失时走完整事实提取流程 |

## 资料识别要点

1. 确认资料范围：正文覆盖到第几章，是否包含最新章节。
2. 确认资料版本：同一事件是否存在多个版本的描述，以最新正文为准，旧版本标注待核实。
3. 确认资料来源：区分用户确认的内容、AI 生成未确认的内容、原始大纲内容。
4. 确认资料完整性：跳章、缺章时明确指出信息缺口，不臆测缺章内容。

## 前文检索策略

1. **按需检索**：根据当前任务确定需要检索的范围，不必每次重读全部正文。
2. **就近优先**：续写任务优先检索最近 1-3 章；涉及老角色或老伏笔时，回溯其首次出现和最近一次出现的章节。
3. **锚点检索**：以人物名、地名、物品名、事件名、伏笔关键词为锚点，定位相关章节段落。
4. **原文留存**：检索到的关键事实必须保留原文语句和章节位置，供后续核查引用。

## 长文本处理

- 正文过长无法一次读入时，分章节处理，先提取每章事实摘要，再汇总成状态快照。
- 每章处理时记录：章节编号、章节标题、主要事件、出场人物、时间地点、结尾状态。
- 多章汇总后交叉核对：人物状态是否连贯、时间是否递进、地点迁移是否合理。

## 输出要求

资料接入完成后，向用户简要报告：

1. 已识别的资料类型和覆盖范围（如：正文 1-42 章，大纲 1-50 章规划）。
2. 发现的版本差异或信息缺口。
3. 本次工作将采用的资料基准。
