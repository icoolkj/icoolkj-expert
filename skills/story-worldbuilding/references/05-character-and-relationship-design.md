# 05 人物与关系体系设计

## 1. 人物在系统中的位置

世界观里的人物不是"角色介绍"，而是**世界规则的压力测试点**。

每个重要人物应能回答：这套世界规则如何塑造了他，他又如何反过来暴露规则的漏洞。

**纪律**：人物档案中的"能力"必须引用已有规则编号（RULE-xxx），不得出现规则之外的能力。这是防止人物越界的第一道闸。

## 2. 人物档案标准格式

```
CHAR-000 姓名（别名）
──────────────────────────────
年龄        具体年龄 + 关键时间点的年龄
身份        社会身份 + 真实身份（如有隐藏）
外貌        3 个可视觉化特征（供视觉设计直接使用）
性格        行为模式，不是形容词堆砌
背景经历    3–5 个关键节点，按时间排列
核心目标    他想要什么（外部、可验证）
内在需求    他真正缺什么（内部、他未必自知）
核心恐惧    最怕发生什么（决定他在关键时刻的选择）
重要秘密    谁知道、谁知道多少（信息差是情节引擎）
能力与限制  引用 RULE 编号 + 个人短板
所属势力    FACTION 编号 + 实际立场
重要关系    CHAR 编号 + 关系类型 + 依据
关键经历    造成当下性格的那一件事
成长弧线    从什么状态到什么状态，转折点在哪
当前状态    故事开始时的处境
设定版本    v1.0
──────────────────────────────
```

### 性格的写法

不要写"冷酷但内心温柔"。写行为：

| 无效写法 | 有效写法 |
|---|---|
| 他很善良 | 他会把最后一瓶水给陌生人，然后骗自己说不需要 |
| 他很强 | 他打赢过三次比自己强的对手，每次都靠拖延到对方力竭 |
| 她很聪明 | 她习惯先记下所有人说谎时的小动作，再决定跟谁合作 |

## 3. 动机结构：四层模型

| 层 | 内容 | 作用 |
|---|---|---|
| 表层欲望 | 他嘴上说要什么 | 推动日常行动 |
| 真实目标 | 他实际在追什么 | 决定主线 |
| 内在需求 | 他缺什么才完整 | 决定结局 |
| 核心恐惧 | 他宁可毁掉一切也不愿面对什么 | 决定高潮的选择 |

**张力来源**：真实目标达成会让他失去内在需求的满足。例如"他要复仇（目标），但他需要的是被原谅（需求），复仇成功就永远得不到原谅"。

## 4. 秘密与信息管理

每个重要秘密必须记录四项：

| 项 | 说明 |
|---|---|
| 内容 | 秘密是什么 |
| 知情者 | 谁已经知道（CHAR 编号） |
| 部分知情者 | 谁知道哪一部分，误以为什么 |
| 揭示计划 | 在第几阶段、由谁、以什么方式暴露 |

**纪律**：秘密若无人知晓也无人可能发现，它就不构成情节，只是作者的自留地。至少安排一条发现路径。

## 5. 人物关系设计

### 5.1 关系必须写"依据"

| 字段 | 说明 |
|---|---|
| A | CHAR 编号 |
| B | CHAR 编号 |
| 关系类型 | 血缘/师徒/盟友/上下级/仇敌/恋人/债主/交易/镜像 |
| 关系依据 | 因何事建立（必须具体到事件） |
| 强度 | 1–5（能否为对方去死/能否背叛） |
| 当前状态 | 稳定/紧张/破裂/表面维持 |
| 变化节点 | 在什么条件下升级或破裂 |
| 信息不对称 | A 知道 B 什么，B 不知道 A 什么 |

没有"依据"的关系就是设定漏洞：读者会问"他们凭什么"。

### 5.2 关系网的四类结构位

| 位置 | 功能 | 数量建议 |
|---|---|---|
| 支点 | 主角，所有关系汇聚 | 1 |
| 镜像 | 处境相似、选择相反，用来说透主题 | 1–2 |
| 拉力 | 把主角往旧生活拉的人 | 1–2 |
| 推力 | 逼主角改变的人 | 1–2 |
| 功能 | 提供信息/制造障碍/代读者提问 | 按需，宜少 |

**纪律**：每个配角至少承担一个功能。三个功能都没承担的，合并或删除。

### 5.3 关系张力表

比"关系列表"更有用：

| 人物 | 与主角关系 | 立场 | 能给主角什么 | 会夺走什么 | 关系走向 |
|---|---|---|---|---|---|
| | | 同盟/对手/摇摆/镜像 | 资源/信息/情感/能力 | 安全感/退路/身份/信任 | 靠近/背离/反转 |

## 6. 人物与世界的三重绑定

人物必须在三个方向上与世界咬合，否则会悬浮。

| 绑定方向 | 内容 | 检验 |
|---|---|---|
| 规则绑定 | 他的能力来自哪条规则，受什么限制 | 若无规则支撑，能力是外挂 |
| 制度绑定 | 他在社会结构里的位置决定他的困境 | 换到另一个阶层，故事是否仍成立 |
| 历史绑定 | 他的伤口由哪个历史事件造成 | 该事件是否在时间线上 |

**加分项**：让人物的私人问题与世界级问题同构。他一个人面对的困境，正是这个世界整体面对的困境。

## 7. 成长弧线的可执行写法

| 阶段 | 状态 | 触发事件 | 选择 | 结果 | 代价 |
|---|---|---|---|---|---|
| 起点 | | | | | |
| 第一次动摇 | | | | | |
| 中点转变 | | | | | |
| 最低点 | | | | | |
| 终点 | | | | | |

**纪律**：成长必须有代价，且代价必须是**他曾经最看重的东西**。没有代价的成长是升级打怪。

## 8. 人物数量控制

| 项目规模 | 详写人物 | 列名人物 |
|---|---|---|
| 短篇 | 3–5 | 5 以内 |
| 中长篇 | 8–15 | 20 以内 |
| 长篇 | 15–30 | 不限，但必须有索引 |

超过这个量级，读者会记不住，作者会写崩。控制方式：合并功能重复的人物。

## 9. 人物一致性检查

交付前逐项过：

| 检查 | 问题 |
|---|---|
| 能力越界 | 他用的能力是否在规则允许范围内 |
| 信息越界 | 他做的判断是否用到了不该知道的信息 |
| 动机漂移 | 他的行为是否与核心目标/恐惧冲突且无解释 |
| 年龄错位 | 他与关键事件的时间差是否合理 |
| 关系突变 | 关系变化是否有对应事件 |
| 功能冗余 | 是否有两个人物功能完全重复 |
| 工具人化 | 他是否有与主角无关的自己的事 |
