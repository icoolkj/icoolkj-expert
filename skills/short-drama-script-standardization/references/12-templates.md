# 12 交付模板索引与填写要求

模板文件位于 `assets/`，交付时复制并填写，不要在原模板上直接改。

## 12.1 模板清单

| 文件 | 用途 | 交付建议 |
| --- | --- | --- |
| `standard_script_template.md` | 标准化剧本骨架 | 必交 |
| `structure_inventory_template.md` | 集/场/人物/场景清单 | 必交 |
| `issue_report_template.md` | 质量审查报告 | 必交 |
| `change_log_template.md` | 修改记录 | 有修改必交 |
| `handoff_template.md` | 制作交接说明 | 进入制作阶段必交 |

## 12.2 标准化剧本骨架

必须包含：

- 项目名、集号、集标题（无标题则不写）
- 场次标题四要素
- 人物行
- `△ ` 动作行
- 对白（署名 + 可选提示 + 换行台词）
- 标注
- 集末 `【本集完】` 或项目约定的结束标记（若项目使用）

不得包含：目录、批注、修订痕迹、分镜表、Prompt。

## 12.3 结构清单填写要求

- 场次清单必须覆盖**全部**场次，不允许"其余略"。
- 人物出场表必须包含全部有署名的角色，包括群体。
- 场景清单按出现次数降序排列，便于制片识别主场景。
- 标注清单只统计成对标记与特殊标记，不必逐条列出音效。

## 12.4 质量审查报告填写要求

- 按 P0 → P3 排序，同级按场次顺序。
- 每条必须能被定位（场号 + 元素）。
- 结论列只能是四值：`通过 / 问题 / 不适用 / 未覆盖`。
- 报告开头写"覆盖范围"与"未覆盖范围"。
- 结尾写"本报告不含导演、制片、合规评估"。

## 12.5 修改记录填写要求

- 每条对应一个具体位置，批量修改注明处数。
- "修改前"必须引用原文，不得转述。
- 建议未采用的，状态写 `未采用`，不得省略。
- 用户裁决的，操作者写 `用户决定`。

## 12.6 交接说明填写要求

见 `13-delivery-handoff.md`。核心是：让制片/导演能在 5 分钟内知道"这个本子要拍什么、缺什么、风险在哪"。


## 12.8 交付时的口头摘要

交付消息里应当包含：

1. 处理了哪些集、多少场。
2. 格式修复数量级。
3. 内容改动：有/无（有则列出）。
4. 待确认事项数量与最关键的 1–3 条。
5. 未覆盖范围。
6. 一句话说明"标准化不等于导演/制片通过"。

## 12.9 生成文件后的自检

- [ ] 文件真实存在且可打开
- [ ] 文件名符合规范
- [ ] 集数、场次数与结构清单一致
- [ ] 无占位未填（`TODO`、`xxx`、`【待补】`）
- [ ] 模板中的说明性文字已删除
- [ ] 所有交付物互相引用一致（报告编号与记录编号对应）
