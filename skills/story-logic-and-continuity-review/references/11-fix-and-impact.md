# 11 修复方案与影响分析（M11）

## 1. 问题生命周期

```
待确认 → 已确认 → 修复中 → 待复审 → 已关闭
   ↓                            ↑
保留原设计（作者决定不改）      └── 复审不通过 → 退回修复中
```

| 状态 | 含义 | 谁能推进 |
|---|---|---|
| 待确认 | 审校方提出，作者尚未表态 | 作者 |
| 已确认 | 作者认可问题存在 | 作者 |
| 修复中 | 作者或创作者正在修改 | 作者/创作者 |
| 待复审 | 修改完成，等待审校 | 创作者 |
| 已关闭 | 复审通过 | 审校方 |
| 保留原设计 | 作者明确决定不改（须记录理由） | 作者 |

**"保留原设计"不是不了了之**：必须记录作者理由，并在后续审校中不再重复提出同一问题，避免骚扰式重复。

---

## 2. 修复方案的三层结构

每个问题提供三档，按优先级排列：

### A. 最小修改方案（默认推荐）
- 原则：只改必要的字句，不动结构、不动人物命运。
- 常见手法：加一句过渡、加一个细节信号、改一个词（时间、方向、数量、称谓）、删一句越界表述。
- 优点：风险最低，作者接受度高。
- 缺点：有时只能"掩盖"而非"解决"。

### B. 替代修复方案
- 原则：从另一侧修正（改前面的铺垫，而非后面的结果）。
- 常见手法：在前文补建立、调整因果前置条件、更换解围手段。
- 优点：可能更彻底。
- 缺点：改动面更大，可能影响其他章节。

### C. 保留原设计的解释方案
- **仅在确实合理时提供**：即该设计有艺术价值，只需补一句让读者接受。
- 常见手法：给人物一句自嘲、给叙述者一个视角说明、把"漏洞"变成"人物的错误认知"。
- 注意：不得用此方案为真正的逻辑错误开脱。

**禁止的做法**：直接给出重写后的完整段落并要求作者采用。审校者提供的是方案，不是成品。

## 3. 影响范围分析法

### 3.1 六层影响扫描

从问题点向六个方向扩散，逐层确认是否受影响：

| 层 | 内容 | 检查方法 |
|---|---|---|
| L1 当前场景 | 前后段落是否依赖该事实 | 就近阅读 |
| L2 直接关联事件 | 由该事实导致的事件 | 查因果链表 |
| L3 相关人物 | 该人物的状态、认知、关系 | 查状态快照与认知台账 |
| L4 后续章节 | 所有引用该事实的位置 | 关键词检索（人名、物名、数字、地名） |
| L5 关联设定文件 | 设定文档、人物档案、资产 | 跨媒介对照 |
| L6 主线 | 是否影响核心冲突、主题、结局 | 判断是否改变故事走向 |

### 3.2 检索关键词的构造

修复前必须做一次全文检索，关键词包括：

- 涉事人物名 + 所有称谓（官职、昵称、代号、他人称呼）
- 涉事物件名 + 所有别名
- 涉事地点名
- 具体数字（年龄、距离、时间、人数、钱数）
- 相关动词（受伤、痊愈、丢失、赠予、抵达）
- 时间词（三日后、次日、那年、十年前）

检索结果逐条核对，这是防止"改一处崩三处"的唯一可靠方法。

### 3.3 连锁反应三类

1. **事实连锁**：改了 A，B 的表述变错。
2. **动机连锁**：改了行为，动机不再成立。
3. **情感连锁**：改了事件，人物关系的基础动摇。

三类都要查。最容易漏的是第三类。

## 4. 修复方案的评估维度

给作者的方案表应包含：

| 维度 | 说明 |
|---|---|
| 改动量 | 涉及几处、几章、几个文件 |
| 风险 | 可能引发的连锁问题 |
| 对人物影响 | 是否改变人物弧线 |
| 对节奏影响 | 是否增加篇幅、拖慢节奏 |
| 对主题影响 | 是否削弱主题表达 |
| 接受度建议 | 审校方推荐哪个，为什么 |

**推荐语写法**："建议采用 A，因为改动仅一句，且不触碰第 30 章之后的所有依赖；若作者希望保留'能力突破'的爽感，则 B 更合适，但需同步处理第 33 章。"

## 5. 复审流程

### 5.1 复审前置条件
- 作者已提交修改稿（明确版本号）。
- 原审校报告（含问题编号）在手。
- 修改说明（改了哪里）最好有；若没有，需自行定位。

### 5.2 复审三步

**第一步：逐条核对**
对每个问题，判定四种结果之一：

| 结果 | 含义 |
|---|---|
| 已解决 | 原冲突不再存在 |
| 部分解决 | 主要冲突消除，但残留表述仍不一致 |
| 未解决 | 未作修改，或修改无效 |
| 已转化为新问题 | 修改后冲突改变形态 |

**第二步：回归检查**
- 修改处是否引入了新的矛盾？
- 是否影响了其他已确认事实？
- 是否破坏了人物动机、情绪线、时间线、伏笔？
- 是否需要同步更新设定文档、资产、其他媒介版本？

**第三步：抽样重扫**
对修改点前后各一章做一次快速通读（模式 A 标准），捕捉修改带来的次生问题。

### 5.3 复审结论的四档

| 结论 | 条件 |
|---|---|
| 通过 | 全部 P0/P1 已解决，无新增 P0/P1 |
| 有条件通过 | P0/P1 已解决，但存在新增 P2 需在下一版处理 |
| 需再修 | 仍有未解决的 P0/P1 |
| 不通过 | 修改引入了新的 P0/P1 |

## 7. 输出模板示例

```
### 问题编号：TIME-001（修复建议）
- 源头位置：第 13 章「第三日黄昏」
- 派生位置：第 14 章「赶在寿宴前一日」；第 16 章「追兵慢了半日」
- 检索关键词：三日、四日、寿宴、追兵、凉州、临安
- 方案 A（推荐）：第13章改"第五日黄昏"；第14章"前一日"改为"当日"；
  第16章"慢了半日"改为"慢了一日"。共 3 处字词，不动情节。
  · 改动量：3 处 / 1 章 / 0 文件
  · 风险：低。第14章时间压力反而更紧，符合原有意图。
  · 对人物/节奏/主题：无影响。
- 方案 B：第5章驿马速度改"日行三百里"，并补换马细节。
  · 改动量：1 处 + 补写 2 句
  · 风险：中。第20章"追兵慢半日"的论证需重算；马匹疲惫描写需补齐。
  · 优点：一次性解决全书所有行程问题。
- 方案 C（保留原设计）：不改时间，改第13章为"他记错了日子，其实已过五日"，
  把行程误差转为主角的疲惫失误。
  · 需补：一处主角看错日期的细节。
  · 代价：削弱主角的精细人设。
- 复审要点：重算第12–16章全部时间节点；确认第16章追兵时间差；确认马匹状态描写。
```
