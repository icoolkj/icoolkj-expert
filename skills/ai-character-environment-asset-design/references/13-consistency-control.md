# 13｜一致性控制与排错

## 1. 一致性的四个层级

| 层级 | 内容 | 检查方式 |
|------|------|----------|
| L1 风格一致 | 全项目画风、色彩、光比统一 | 缩略图拼贴，看是否像同一部片 |
| L2 身份一致 | 同一角色 / 场景跨图可识别 | 并排比对识别特征 |
| L3 状态一致 | 状态变化符合剧情连续性 | 对照登记表逐场核对 |
| L4 空间一致 | 多视角可反推同一平面 | 平面核对 + 门窗位置检查 |

任何一层失守，后续生产都会放大错误。

## 2. 角色一致性失败模式

| 症状 | 根因 | 修正 |
|------|------|------|
| 每次生成脸型微变 | 识别特征未量化 | 把特征改写成可观测描述（尺寸、位置、角度） |
| 换个角度就变人 | 侧脸/背面信息缺失 | 补侧面与背面文字设定 + 侧脸参考图 |
| 换装后像换了演员 | 服装承担了识别任务 | 强化面部与体态特征，弱化服装独特性 |
| 表情图之间不像同一人 | 表情描述压过了身份描述 | 身份段前置且加权重 |
| 近景对、远景不对 | 远景缺乏特征细节 | 远景依赖剪影与色彩标签，不依赖五官 |
| 手部每次都崩 | 手部描述缺失 | 每张涉及手部的图明确手部姿态 + 负面词 |

## 3. 场景一致性失败模式

| 症状 | 根因 | 修正 |
|------|------|------|
| 反打镜头门窗位置反了 | 无平面 | 建立平面后再生成 |
| 材质颜色漂移 | 材质表只写名称 | 补 HEX 与表面处理 |
| 阴影方向矛盾 | 无光位约定 | 视觉圣经锁定主光方位 |
| 尺度不对 | 无参照物 | 画面中加入人物或标准尺寸物 |
| 同一房间两次生成风格不同 | 无风格锚点 | 复用场景主视觉作参考图 |

## 4. 跨批次一致性

批量生成时：
1. **锁定一个"母版"**：每类资产选一张审核通过的图作为母版。
2. **母版优先作为参考图**，而非用文字重述。
3. **固定随机种子组**：同一角色的资产尽量在同一 session / 同一参数下生成。
4. **批次记录**：每批记录模型版本、参数、时间。模型升级会导致漂移，需重新校准。
5. **抽检**：每批抽 10% 与母版比对，发现漂移立即停下排查。

## 5. 一致性检查报告模板

```markdown
# 视觉一致性检查报告
项目：XXX　检查日期：YYYY-MM-DD　批次：B03

## 检查范围
角色：CHAR-001, CHAR-002　场景：ENV-003　道具：PROP-007

## 结果
| 资产 | 检查项 | 结论 | 问题描述 | 处理 |
|------|--------|------|----------|------|
| CHAR-001-C02 | 面部识别特征 | 通过 | — | — |
| CHAR-001-C02 | 左眉断眉疤 | 不通过 | 第3张缺失 | 局部重绘 |
| ENV-003-V2 | 门窗位置 | 不通过 | 窗移至南墙 | 重生成 |

## 结论
本批次 12 张中 10 张通过，2 张需返工。

## 待用户确认
- CHAR-001 服装 C02 的袖口是否保留破损【设计建议】
```

## 6. 排错顺序

遇到"像但又不对"的图，按此顺序排查，不要一上来就重写 Prompt：

1. 参考图是否正确（用错参考是最高频错误）。
2. 身份描述是否被后续描述淹没（检查语序）。
3. 是否有冲突词（如同时写 "short hair" 与 "long braid"）。
4. 是否缺少关键视角信息。
5. 模型能力是否足够（换更强模型或加 ControlNet）。
6. 最后才考虑改 Prompt 结构。

## 7. 不可修复的情形

诚实告知用户：
- 模型无法稳定复现极细节（如特定文字、极小的纹身）。
- 极端角度（大俯大仰）下的身份保持。
- 同一画面多个已知角色同框且都需精确还原。

对应策略：后期合成、局部贴图、分层生成后拼合。
