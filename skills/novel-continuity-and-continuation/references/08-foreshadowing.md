# 08｜伏笔生命周期管理

## 伏笔台账

每条重要伏笔建立独立记录：

```
【伏笔编号】FB-001
【伏笔内容】一句话描述悬念本体
【首次出现】第X章，原文依据："……"
【涉及人物】
【相关事件】
【预期作用】（回收时应揭示什么/推动什么）
【已有提示】
  - 第Y章：以何种方式强化
【计划回收位置】（用户确认过的计划；未确认则标注待确认）
【当前状态】（见下）
【回收结果】（回收后填写：第Z章如何回收、是否达成预期作用）
```

## 生命周期状态

```
待铺设 → 已铺设 → 已强化* → 待回收 → 已回收
                ↘ 已废弃          ↘ 已废弃
* 已强化为可选阶段（中途再埋提示）
```

| 状态 | 定义 |
|---|---|
| 待铺设 | 计划中但正文尚未出现的伏笔 |
| 已铺设 | 正文已出现但读者尚不能确认其意义 |
| 已强化 | 已有额外提示，读者可隐约察觉 |
| 待回收 | 铺垫充分，随时可回收 |
| 已回收 | 已在正文中揭示并产生剧情效果 |
| 已废弃 | 用户确认放弃回收（记录原因） |
| 待确认 | 检测到疑似伏笔，尚未与用户确认 |

## 管理规则

1. **主动发现**：解析正文时主动识别疑似伏笔（反常细节、未解释现象、意味深长的对话、未兑现的承诺），登记为待确认，交用户核实。
2. **回收有据**：回收伏笔时，揭示内容必须与铺设时埋下的信息一致——不能回收时改写伏笔本体的含义。
3. **不强行回收**：不得为了回收伏笔而强行改变人物行为或故事因果；时机不成熟就继续铺垫或延后。
4. **不提前揭露**：回收前检查本章剧情进度是否到了计划回收位置；提前揭露会摧毁悬念结构。
5. **强化节奏**：长期未回收的伏笔，建议用户在适当章节补一次轻提示，防止读者遗忘。
6. **回收留痕**：回收后填写「回收结果」，关联对应事实条目，更新 L4 剧情。
7. **废弃留痕**：废弃伏笔记录原因，且正文中不应再留下指向该伏笔的新提示（否则读者会觉得烂尾）。

## 伏笔追踪模式交付格式

- 伏笔总览表：编号、内容、首次出现、当前状态、计划回收位置。
- 重点分析：用户点名伏笔的完整生命周期回溯（铺设原文 → 强化记录 → 回收情况）。
- 建议：长期未回收的伏笔给出铺垫/回收时机建议；疑似被遗忘的伏笔发出提醒。

## 定期健康检查（连续性审查时执行）

- 是否有伏笔超过计划回收位置仍未回收？
- 是否有伏笔的关键提示与新剧情矛盾？
- 是否有新剧情无意中提前揭穿了某伏笔的答案？
- 悬念密度是否失衡（某卷堆积过多未回收伏笔）？
