# 10 问题分级与修改权限

本文件决定"哪些可以直接改、哪些只能报告"。这是全流程最容易越界的地方。

## 10.1 等级定义（P0–P3）

| 等级 | 定义 | 判断标准 | 时限含义 |
| --- | --- | --- | --- |
| P0 | 严重影响理解或无法制作 | 结构断裂、场次缺失、空场、人物无名导致分不清谁说 | 必须解决后才能交付 |
| P1 | 影响人物、场景、连续性 | 署名不统一、地点名不一致、内外景与内容矛盾、时间冲突 | 交付前应解决 |
| P2 | 格式或表达不规范 | 标点混用、标注符号不统一、动作抽象、标注密度过高 | 交付前修格式，表达类给建议 |
| P3 | 优化建议 | 节奏、密度、可读性、超长台词、无动作插入点 | 不阻塞交付，列出即可 |

等级与"能不能改"是两件事：P0 也可能是 C 类（只能报告），P2 也可能是 A 类（可直接改）。

## 10.2 修改权限（A/B/C）

| 类别 | 定义 | 权限 | 典型事项 |
| --- | --- | --- | --- |
| A 类 | 纯格式，不改变任何语义 | 可直接修复，记入修改记录 | 标点、括号、空行、符号统一、场号补零、集标记写法、署名统一（已确认同一人） |
| B 类 | 表达规范，涉及措辞或呈现 | 保留原意优先；涉及新增动作/对白/可视化表达只作建议 | 抽象动作可视化、过长台词切分、表演提示改写、场景补充描述 |
| C 类 | 内容层面 | 只报告，不修改 | 剧情漏洞、人物关系矛盾、时间线冲突、信息提前泄露、场次结构问题、缺失场次 |

判定口诀：**改字不改意 → A；改呈现不改事实 → B（建议）；改事实 → C（仅报告）。**

## 10.3 判定表（常见事项）

| 事项 | 等级 | 类别 | 处理 |
| --- | --- | --- | --- |
| 集标记写成"第一集" | P2 | A | 改为 `第01集`，记录 |
| 场号缺 `1-` 前缀 | P2 | A | 补前缀，记录 |
| 半角括号改全角 | P2 | A | 直接改 |
| `...` 改 `……` | P2 | A | 直接改 |
| 署名"苏总"→"苏瑾"（已确认同一人） | P1 | A | 改署名，不改台词内容 |
| 署名"苏总"疑似另一人 | P1 | C | 不合并，报告 |
| 地点"公寓"/"苏瑾公寓"混用 | P2 | A | 统一为标准名，记录 |
| 场景缺内外景 | P1 | B | 可推定则补并注明依据；否则待确认 |
| 场次标题含剧情描述 | P2 | A | 把剧情移入动作行，标题只留四要素 |
| 动作"她很痛苦" | P2 | B | 原文保留，给可视化建议 |
| 动作混入"特写" | P1 | A（剥离） | 剥离到建议栏，记录原文 |
| 动作混入英文 Prompt | P1 | A（剥离） | 剥离，记录 |
| 台词有错别字 | P2 | A | 改，记录；方言用字不改 |
| 台词语病/口头禅 | P3 | B | 保留，仅提示，不建议强改 |
| 台词超长 | P3 | B | 建议切分，不擅自切 |
| 空台词（署名无内容） | P1 | B | 补 `（沉默）` 或改动作行，须确认 |
| 空场 | P0 | C | 报告，不补写 |
| 场号重复 | P0 | A（重排）+ C（原因） | 重排并说明依据 |
| 人物行缺失 | P1 | B | 可推定则补，否则待确认 |
| 人物关系矛盾 | P1 | C | 只报告 |
| 时间线冲突 | P1 | C | 只报告 |
| 闪回未闭合 | P1 | A（补闭合） | 若上下文明确则补 `【闪回结束】`，记录 |
| 成对标注交叉嵌套 | P2 | A | 按语义重排，记录 |
| 一场跨两个地点 | P1 | C | 建议拆场，不擅自拆 |
| 信息提前泄露 | P1 | C | 只报告 |
| 疑似重复场次 | P1 | C | 并列展示，请用户裁决 |
| 集与集衔接断裂 | P0 | C | 只报告 |

## 10.4 报告字段

```
编号 | 等级 | 类别 | 位置 | 原文 | 问题说明 | 影响 | 建议处理 | 状态
```

- 编号：`A-01`、`B-07`、`C-12` 按类别分组编号，或统一 `I-001`。
- 位置：`集-场` + 行号或元素类型（`2-4 人物行`、`5-1 第3条动作`）。
- 原文：摘录关键片段，不超过 40 字，用引号包裹。
- 影响：一句话说明会导致什么后果（"配音无法分轨""演员无法判断走位"）。
- 建议处理：具体动作，不写"建议优化"。
- 状态：`已修复 / 建议未采用 / 待用户确认 / 不修改（C类）`。

## 10.5 批量修改的记录方式

同一类 A 类修改涉及多处时，可合并为一条记录：

```
A-03 | 全稿 | 署名"苏总"统一为"苏瑾" | 影响 14 处，涉及 1-3、2-1、2-5… | 已修复
```

但**涉及内容判断的修改不得合并**，必须逐条。

## 10.6 越界自查

完成前自问：

1. 我改的每一处，能否用一句话说明"这不是创作"？
2. 修改记录里，是否有"顺手改了一下"而无依据的条目？
3. 是否有把 C 类问题悄悄改成 B 类处理的情况？
4. 建议栏里，是否有伪装成原文的表述？
5. 是否有为了"读起来顺"而改动了人物语气？

任一项答不上来，回退该处修改并重新归类。

## 10.7 用户裁决的归档

用户对 C 类问题的裁决（改/不改/怎么改）必须记录：

```
C-05 | 用户裁决：接受修改，改为"她其实早就知道" | 裁决时间：2026-11-01 | 已执行
C-08 | 用户裁决：保持原样 | 已标注不修改
```

裁决后由用户承担的修改，仍需在修改记录中体现，但作者标记为"用户决定"。
