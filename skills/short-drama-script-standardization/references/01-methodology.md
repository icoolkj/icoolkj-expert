# 01 总体方法：从原稿到标准化交付

本文件是 S06 的方法总纲。处理任何剧本前先读本文件，确定"这次到底做什么、做到哪一步、什么不能碰"。

## 1.1 三条不可越过的边界

| 边界 | 含义 | 越界示例 |
| --- | --- | --- |
| 不做二次创作 | 不新增剧情、不新增人物、不重写台词 | 原稿写"两人争吵"，标准化时补出具体吵架台词 |
| 不做导演工作 | 不写景别、机位、运镜、分镜表 | 在动作行里写"特写苏瑾的眼睛，缓慢推近" |
| 不做制片判断 | 不评估成本、档期、演员、过审风险等级 | 断言"这场爆破戏成本过高建议删除" |

发现上述层面的问题，只能写进审查报告的建议栏，不得落进剧本正文。

## 1.2 阶段编排（对应 SKILL.md 八步流程）

```
认稿 → 定标 → 建账 → 施工 → 复核 → 交付 → 归档
```

1. **认稿**（第一步）：判断输入是什么、覆盖哪些集、完整度如何。
2. **定标**（第二步）：确认格式规范来源，写入本次任务的"临时规范卡"。
3. **建账**（第三步）：抽出集/场/人物/场景/标注五本账，此阶段一个字都不改。
4. **施工**（第四步）：按固定顺序做八项标准化，每项完成后记账。
5. **复核**（第五步）：机械项用 `scripts/script_lint.py`，判断项走 `09-quality-check.md`。
6. **交付**（第七步）：按 `12-templates.md` 出件。
7. **归档**（第八步）：按 `11-version-management.md` 记录版本与修改。

## 1.3 认稿：输入形态判断表

| 形态 | 识别特征 | 处理策略 |
| --- | --- | --- |
| 完整剧本（多集） | 有集标记、逐场推进、有完整对白 | 整体解析，先出全局结构清单再动工 |
| 单集剧本 | 仅一集，场次完整 | 按单集处理，集号以原稿为准 |
| 分集大纲 | 每集一段概要，无场次无对白 | 只做层级与编号标准化，**不做场次化拆解**；如需拆分场次属于创作，须用户明确委托 |
| 场次大纲 | 有场次编号但内容为概述 | 保留概述性表述，不补对白 |
| 剧本初稿 | 结构在、格式乱、时有段落缺失 | 全量格式施工 + 重点标注缺失信息 |
| 剧本修改稿 | 有修改痕迹、批注、多色标注 | 先剥离批注，批注内容单列进待确认清单 |
| 剧本评审稿 | 带评审意见、打分表 | 评审意见不得写入正文，另附意见汇总 |
| 多版本剧本 | 同名多文件、带 v1/v2/终版 | 先确认基准版本，逐版比对，禁止混合取材 |

## 1.4 定标：规范优先级

```
用户指定规范 > 用户历史项目模板 > 本 Skill 默认标准
```

冲突时不得"各取一半"。逐条列出冲突点，请用户裁决；未裁决前一律以更高优先级为准，并在报告中标明"待裁决"。

默认规范的核心值：

- 集标记：`第01集`（两位补零）
- 场次编号：`集-场`，如 `1-1`
- 场景标题：`场号 时间 内外景 地点`
- 人物行：`人物：A、B`
- 动作行：`△ ` 开头
- 标注：`【类型：内容】`
- 对白：`人物（提示）：` 换行接台词

## 1.5 建账：五本账的最小字段

| 账本 | 字段 |
| --- | --- |
| 集账 | 集号、集标题、场次数、是否完整 |
| 场账 | 场号、时间、内外景、地点、出场人物、有无对白 |
| 人账 | 标准名、别名/称谓、身份、首次出场、出现场次 |
| 景账 | 场景名、出现场次、内外景、备注 |
| 标注账 | 标注类型、出现位置、写法、是否统一 |

账本先出，再施工。账本与正文不一致时，以正文事实为准，反过来修账本。

## 1.6 不确定性处理：三档判定

| 档位 | 判定条件 | 处理方式 |
| --- | --- | --- |
| 可推定 | 原稿其它位置已有明确答案，且不涉及创作 | 直接补全，记入修改记录并注明依据位置 |
| 需确认 | 有两种以上合理解释，或涉及人物身份/关系/时间 | 保留原样，列入待确认清单，正文可加 `【待确认：…】` |
| 禁止编造 | 原稿完全无信息（如无名配角姓名、具体地点名） | 保持原稿写法（如"黑衣人""某咖啡馆"），不得命名 |

判定口诀：**能查到的补，查不到的标，猜得到的写进建议。**

## 1.7 施工顺序为什么不能乱

1. 先结构后文字：结构没定就改标点，后面重排会全部返工。
2. 先人物后对白：人物名不统一就改对白格式，会出现同一人被格式成两个名字。
3. 先场景后动作：场景地点定不下来，动作描述里的方位词无从校验。
4. 先内容后标点：标点整理放最后，避免改一次内容再修一次标点。

## 1.8 交付前自检（十条）

- [ ] 原稿每一场都能在标准化稿中找到对应场次，无丢失。
- [ ] 场次编号连续或差异已说明。
- [ ] 集号、场号与结构清单一致。
- [ ] 人物标准名全稿唯一，别名有映射表。
- [ ] 每场人物行与场中对白人物一致（或差异已标注）。
- [ ] 所有 `【` 都有配对的 `】`。
- [ ] 动作行都有执行主体。
- [ ] 没有把分镜、Prompt、批注混进正文。
- [ ] 修改记录覆盖了每一处非格式性改动。
- [ ] 待确认清单不为空时有明确条目，不是"暂无"敷衍。

## 1.9 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 一边读一边顺手改 | 无修改前原文，无法回溯 | 先建账留底，再施工 |
| 为了整齐删重复场次 | 丢失原稿事实 | 重复场次保留并报告疑似重复 |
| 把"她想哭"改成"她落泪" | 改变了表演与信息 | 原文保留，建议栏给可视化选项 |
| 统一给所有人物加性格标签 | 抹平人物 | 只做名称统一，不动语言风格 |
| 用模板字段倒推剧情 | 虚构信息 | 字段留空 + 待确认 |
| 直接输出"已完成审校" | 过度承诺 | 说明检查了哪些项、哪些未检查 |

## 1.10 与其他 Skill 的衔接

- 上游若来自大纲/分集规划：只接已成稿的剧本文本，不接大纲生成职责。
- 下游若进入分镜、拍摄、AI 视频生成：本 Skill 只交付标准剧本，分镜与 Prompt 由下游产出，不写入正文。
- 若用户要求同时做"标准化 + 修改剧情"：拆成两个任务，先交付标准化稿，再单独走修改流程，避免责任混淆。
