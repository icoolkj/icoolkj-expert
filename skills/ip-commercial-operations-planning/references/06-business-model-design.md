# 06 商业模式设计

## 0. 原则

不做"收入方式大礼包"，只做**三档排序**：现在做 / 下一步做 / 暂不做。每一档都要给准入条件和放弃理由。

## 1. 七类收入

| 类 | 具体方式 | 适合阶段 | 关键前提 | 主要风险 |
|---|---|---|---|---|
| A 内容收入 | 付费阅读、会员订阅、短剧付费、平台分账、音频/出版 | P2–P3 | 稳定内容供给、平台分成机制清晰 | 分成不透明、单价被压 |
| B 流量收入 | 创作者激励、广告、品牌植入、内容推广 | P2–P4 | 稳定流量、内容承载力 | 广告伤内容、单价波动 |
| C 商务收入 | 品牌合作、联合营销、定制内容、商业活动 | P3–P4 | 有案例、有受众数据 | 交付压力、调性冲突 |
| D 授权收入 | 形象授权、名称/标识授权、改编授权、商品授权、跨媒介授权 | P3–P4 | 权利清晰、资产分级、审核能力 | 超范围使用、质量事故 |
| E 商品收入 | 周边、收藏品、出版物、主题商品、联名商品 | P3–P4 | 视觉资产、供应链、库存管理 | 压货、退货、侵权 |
| F 体验收入 | 线下活动、主题展、角色互动、主题空间 | P4 | 粉丝密度、场地资源 | 客流不足、安全与合规 |
| G 衍生内容收入 | 漫画、动画、游戏、音频剧、影视改编 | P3–P4 | 改编权、合作方、投资 | 开发周期长、改编失真 |

## 2. 评估矩阵

每个候选模式逐项打 1–5 分，总分只用于排序，**任何一项 ≤2 分即视为不具备准入**。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 用户需求 | 无付费动机 | 有零星付费 | 明确且已被验证 |
| 市场条件 | 渠道不成熟 | 有渠道但门槛高 | 渠道成熟、规则透明 |
| 阶段匹配 | 超前两阶段 | 差半阶段 | 完全匹配 |
| 生产成本 | 高且不可控 | 可控但占比高 | 低边际成本 |
| 运营成本 | 需专职团队 | 半职可承接 | 现有产能可覆盖 |
| 供应链要求 | 需自建供应 | 需稳定外部供应 | 无供应链依赖 |
| 版权条件 | 权利不明 | 部分权利在手 | 权利完整 |
| 执行难度 | 需跨行业能力 | 需学习成本 | 现有能力可执行 |
| 风险 | 可能伤品牌 | 可控 | 低风险可逆 |

## 3. 三档输出格式

| 档位 | 模式 | 理由 | 准入条件 | 首月动作 | 止损线 |
|---|---|---|---|---|---|
| 现在做 | | | | | |
| 下一步做 | | | 触发条件（如粉丝达 x / 付费率达 y） | | |
| 暂不做 | | 明确放弃理由 | — | — | — |

"暂不做"必须写理由，这是方案可信度的来源。全部列为"要做"等于没有判断。

## 4. 收入结构健康度

| 检查项 | 健康 | 警戒 |
|---|---|---|
| 单一收入占比 | <60% | >80% |
| 平台依赖度 | 主平台 <70% | >90%（一次规则变动归零） |
| 大客户依赖度 | 单客户 <30% | >50% |
| 现金回收周期 | <60 天 | >120 天 |
| 固定成本占比 | <40% | >70%（抗波动能力差） |

## 5. 定价逻辑

| 方法 | 适用 | 做法 |
|---|---|---|
| 价值锚定 | 内容付费 | 与同类单集/单本/会员价对齐，说明差异 |
| 成本加成 | 实体商品 | 成本 × 倍率（标 E4，说明行业常见区间） |
| 阶梯定价 | 会员/社群 | 基础/进阶/尊享，权益必须真实可交付 |
| 组合定价 | 首发/礼盒 | 用组合提升客单，不做虚假原价 |
| 拍卖/限量 | 收藏品 | 限量必须有真实上限与编号 |

## 6. 常见反模式

| 反模式 | 问题 | 替代做法 |
|---|---|---|
| 先做周边再验证需求 | 压货 | 先预售/意向收集 |
| 免费换流量 | 用户结构失真 | 低价试用 + 明确付费点 |
| 低价授权抢案例 | 锚定过低，后续涨价难 | 首单给资源不给低价 |
| 同时开 4 条变现线 | 全部做不好 | 一次只推 1 主 1 辅 |
| 把平台激励当商业模式 | 政策一变即失 | 激励视为补贴，不作为主营 |
| 承诺销量换合作 | 履约风险 | 只承诺交付，不承诺结果 |

## 7. 输出要求

```
1. 现状收入结构（有数据用 E1，无则写"尚无收入"）
2. 候选模式清单 + 评估矩阵
3. 三档排序（现在/下一步/暂不做），每档给准入与止损
4. 优先模式的单位经济测算（引用 11 号文件）
5. 收入结构健康度自检
6. 下一步验证动作（1–2 个，低成本）
```
