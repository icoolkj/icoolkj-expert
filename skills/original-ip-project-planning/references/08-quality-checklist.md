# 08 质量检查清单

## 使用方式

输出最终版本前逐项过一遍。分三级：

- **P0 致命**：不通过则不得交付，必须修正或明确标注为待解决。
- **P1 重要**：不通过应修正，或在"待确认事项"中说明。
- **P2 优化**：视项目规模决定是否处理。

判定时写"通过 / 不通过 / 不适用"，不通过必须写出具体修正动作。

---

## A. 忠于原始创意（P0）

- [ ] A1 用户核心创意未被替换：一句话故事的主角、目标、核心矛盾，与用户原始表述一致。
- [ ] A2 用户的"明确不做"被遵守，没有偷偷加入被排除的元素。
- [ ] A3 所有 `[专家建议]` 未被写成 `[已确认]`。
- [ ] A4 若提出方向性调整，已说明"原设想 / 调整后 / 调整理由"三者。
- [ ] A5 未将流行套路强行套入，个性设定得到保留。

**常见不通过表现**：把用户的"悬疑+亲情"改成"悬疑+复仇"，并称"这样更有张力"。

## B. 定位清晰（P0）

- [ ] B1 定位语能在 30 字内说清"这是谁的故事、什么体验"。
- [ ] B2 主类型明确，融合类型不超过 2 个。
- [ ] B3 基调前后一致（不出现"既轻松搞笑又压抑致郁"这类矛盾表述）。
- [ ] B4 内容形态与创意特征匹配（见 04 文件"适配判断三问"）。
- [ ] B5 写出了"不服务的人群"。

## C. 核心卖点（P0）

- [ ] C1 主卖点不超过 2 个，且能用一句话转述。
- [ ] C2 每个卖点有对应的具体体现方式（前3章/前3集怎么落地）。
- [ ] C3 差异化陈述使用了"相比A的X，本项目换成Y"格式。
- [ ] C4 差异化不止停留在设定层，人物关系层也有差异。
- [ ] C5 记忆点 ≥2 个，且是可被第三方复述的具体内容。

## D. 主角与冲突成立（P0）

- [ ] D1 主角有具体、可验证的外部目标。
- [ ] D2 主角有内在需求，且与外部目标形成张力。
- [ ] D3 主角有伤口与缺陷，缺陷会造成实际损失（不是"太善良"）。
- [ ] D4 每个阶段主角都有主动选择，无连续两阶段纯被动。
- [ ] D5 三层冲突（外部/关系/内部）均已设计。
- [ ] D6 对手有明确强度与动机，不是纯恶。
- [ ] D7 高潮要求主角做出"最不愿做的选择"，而不只是"变强取胜"。

## E. 故事具备展开空间（P0）

- [ ] E1 阶段规划覆盖全篇，每阶段有目标/阻力/转折/末状态。
- [ ] E2 长篇项目写出了至少前 3 个循环单元或 3 个阶段核心。
- [ ] E3 中段有"新目标+新阻力"的升级机制，避免注水。
- [ ] E4 结局类型明确，并回应开篇提出的问题。
- [ ] E5 系列化项目评估了可扩展性（区域/对手梯度/目标迭代）。

## F. 市场判断的诚实性（P0）

- [ ] F1 未出现编造的市场规模、用户数、收入、成功率数据。
- [ ] F2 引用的数据均标注来源与时间；未检索则明确声明。
- [ ] F3 商业潜力表述使用"潜力/假设/待验证"，而非"必然/确定"。
- [ ] F4 竞品拆解包含至少 1 个失败或短板案例。
- [ ] F5 所有推测性结论都进入 `[待验证]` 清单，并给出验证方式。
- [ ] F6 未将平台规则当作稳定事实陈述（政策类内容均已标注时效）。

## G. 跨媒介规划合理性（P1）

- [ ] G1 未默认所有项目都必须跨媒介。
- [ ] G2 每个候选媒介都回答了"核心体验能否保留"。
- [ ] G3 开发优先级有依据（验证价值 × 成本 × 资产复用）。
- [ ] G4 P2/P3 未被写入"下一阶段任务"。
- [ ] G5 列出了各媒介需新增的资产。
- [ ] G6 提及版权事项时只列"待确认"，未给出法律结论。

## H. 风险与待确认事项（P0）

- [ ] H1 至少识别 3 项主要风险，含等级、影响、应对。
- [ ] H2 "必须解决的问题"是具体问题，不是"需要打磨"这类空话。
- [ ] H3 待确认事项写清了选项与影响，用户可直接勾选。
- [ ] H4 立项建议给出了明确状态（四选一），未模糊处理。
- [ ] H5 附录列出了本次做出的全部假设。

## I. 下一阶段可执行（P0）

- [ ] I1 每项任务都有负责人（专家角色）、输入、产出、前置条件。
- [ ] I2 任务顺序不存在循环依赖。
- [ ] I3 下一阶段任务与项目当前成熟度匹配（不在灵感期要求完整剧本）。
- [ ] I4 用户看完知道"现在该做什么"。

## J. 表达与结构（P2）

- [ ] J1 没有为填模板而生成的空章节或套话。
- [ ] J2 章节顺序符合阅读逻辑：先判断，后细节。
- [ ] J3 关键结论前置（每节开头给出判断，再给依据）。
- [ ] J4 术语一致（同一人物/概念全文同一称呼）。
- [ ] J5 篇幅与项目规模匹配（小项目不超过 3–5 页）。

---

## 交付前三问

1. 用户能否指出"这就是我想写的东西"？若不能 → 回到 A 组。
2. 下游专家能否不问"主角要什么"就直接开工？若不能 → 回到 D 组。
3. 是否有一条结论是没有依据的漂亮话？若有 → 删掉或降级为 `[专家建议]`／`[待验证]`。

## 一票否决项

出现以下任一情况，不得输出为"最终版"：

- 编造市场数据。
- 擅自改变用户核心创意且未标注。
- 主角没有可验证目标。
- 把策划写成了正文。
- 声称已读取参考文件而实际未读。
- 声称其他专家已接手或已完成任务。
