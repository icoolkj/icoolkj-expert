# 01 原创IP项目策划方法论

## 1. 策划的本质

策划不是"把一个灵感写得更长"，而是**把不确定的创作冲动，转化为可判断、可分工、可投入的决策依据**。

一个合格的策划案必须回答四个问题：

1. 这是什么？（定位）
2. 凭什么有人看？（卖点与差异化）
3. 怎么撑得住？（故事结构与发展空间）
4. 下一步谁做什么？（开发路径与交接）

如果一份策划案读完后，仍无法回答"要不要做"和"先做什么"，它就没有完成使命。

## 2. 四层结构

策划工作分四层推进，逐层收敛。上层不稳，下层全部作废。

| 层级 | 内容 | 核心问题 | 失败后果 |
|---|---|---|---|
| L1 创意层 | 一句话故事、核心矛盾、记忆点 | 这个想法有没有"钩子" | 后面写得再好也无人在意 |
| L2 故事层 | 主角、关系、主线、阶段、结局 | 这个钩子能不能撑30万字/30集 | 开头惊艳，中期崩塌 |
| L3 产品层 | 定位、受众、形态、篇幅、平台 | 做给谁看、以什么形态交付 | 内容与渠道错配 |
| L4 开发层 | 资产、分工、优先级、风险 | 谁来做、先做什么、卡在哪 | 立项后无法推进 |

**关键纪律**：L1、L2 未达成共识前，不要展开 L3、L4 的细节。用精美排版掩盖创意空洞，是最常见的无效交付。

## 3. 策划链路（从灵感到立项）

```
原始素材
  → 意图确认（你到底想表达什么）
  → 创意提炼（一句话故事 + 核心矛盾）
  → 故事验证（能否展开、靠什么撑）
  → 定位收敛（类型 + 受众 + 形态）
  → 市场校准（同类参照 + 差异点）
  → 开发规划（媒介路径 + 资产 + 优先级）
  → 风险裁决（做 / 改 / 缓 / 不做）
  → 交接落地（给下一位专家的输入）
```

每一步都应产出**可被否决的结论**。如果每一步的结论都是"很好、可以继续"，说明评估没有真正发生。

## 4. 策划案的信息颗粒度

同一份策划，颗粒度随项目阶段变化：

| 阶段 | 策划深度 | 典型篇幅 | 说明 |
|---|---|---|---|
| 灵感期 | 概念澄清 | 1–3 页 | 判断值不值得往下想 |
| 立项期 | 完整策划案 | 8–20 页 | 判断能不能投入资源 |
| 开发期 | 分卷/分集规划 | 视规模 | 交给主笔/编剧执行 |
| 招商期 | 亮点前置版 | 5–10 页 | 面向外部合作方，重卖点轻过程 |

不要用开发期的颗粒度做灵感期的判断——那会造成大量无效劳动，也会让用户误以为项目已经成熟。

## 5. 不同规模项目的差异化处理

| 项目类型 | 策划重点 | 可省略 |
|---|---|---|
| 单篇短篇小说 | 一句话故事 + 记忆点 + 结局反转 | 跨媒介、长篇阶段规划 |
| 长篇连载网文 | 发展阶段、循环单元、追读钩子密度 | 电影级视听设计 |
| 短剧（竖屏） | 前3集钩子、每集反转、付费卡点 | 复杂世界观 |
| 动态漫 | 分镜可行性、单格信息量、视觉记忆点 | 长篇文戏铺陈 |
| AI影视 | 可生成性（场景/人物一致性）、镜头语言 | 大场面群戏 |
| 跨媒介IP | 核心设定可迁移性、视觉符号、世界观弹性 | 单一媒介的极致技巧 |

**原则**：媒介决定结构，结构决定策划重点。先确认交付形态，再决定策划深度。

## 6. 常见失败模式与对策

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 概念空转 | 大量形容词，无具体人物与事件 | 强制写出一句话故事，且必须含主角+目标+阻力 |
| 设定膨胀 | 世界观写了3万字，故事只有一句 | 设定只保留"会改变主角选择"的部分 |
| 套路拼贴 | 热门元素全塞进去，无内在逻辑 | 找出唯一核心矛盾，无关元素全部让位 |
| 主角被动 | 主角一直被事件推着走 | 检查每个阶段主角是否有主动选择 |
| 中段失控 | 前3章精彩，第10章开始水 | 提前规划第二阶段的"新目标+新阻力" |
| 数据幻觉 | 用"市场很大"替代具体受众画像 | 要求写出"谁在什么场景下看，为什么追下去" |
| 越界交付 | 策划案里塞满正文样章 | 策划只给方向与结构，样章最多作风格示例 |

## 7. 与用户的协作节奏

推荐三段式推进，避免一次性甩出20页文档：

1. **对齐段**：复述用户创意 + 列出已确认/待确认，请用户纠偏。
2. **骨架段**：给出一句话故事、定位、主线三件套，请用户拍板核心方向。
3. **成稿段**：骨架确认后再展开完整策划案，避免在错误方向上做深度劳动。

若用户明确要求"直接给完整方案"，则一次性输出，但在文首集中列出关键假设，便于用户逐条否决。

## 8. 判断"策划是否完成"的三个标准

1. 用户能指着某一页说"这就是我想写的东西"。
2. 下一位专家（主笔/编剧/世界观架构师）拿到交接文档后，不需要再问"主角到底想要什么"。
3. 策划案中每一条正向结论，都能对应一条具体的执行动作或验证动作。

三者缺一，策划未完成。
