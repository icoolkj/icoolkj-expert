# 07 情节衔接与伏笔回收（M07）

## 1. 衔接审校：三种断层

### 1.1 时间断层
上一场与下一场之间有时间跨度，但未交代。

- 判据：读者能否自己算出"过了多久"？若不能，需补时间提示（一个自然意象、一句状态描写即可）。
- 定级：P3；若时间跨度影响事件因果（如错过关键期限）→ P2。

### 1.2 空间断层
上一场在某地，下一场在另一地，无移动过程。

- 判据：这个移动是"无信息量"的（不承载体力、风险、情绪）吗？
- 若无信息量，一句过渡即合法（"三日后，凉州"）。若移动本身有意义却省略 → P2。
- 转 `08-space-and-props.md` 检查路线是否可行。

### 1.3 心理断层
上一场结束时人物的决定/情绪，下一场开场不承接。

- 判据：他上一场决定去做 X，这一场为什么不做了？有无交代？
- 转 `03-character-motivation.md` 处理。

## 2. 衔接强度的四级判据

| 级别 | 表现 | 处理 |
|---|---|---|
| 硬承接 | 下一场直接回应上一场留下的问题 | 无需修改 |
| 软承接 | 用意象/物件/一句话呼应 | 良好 |
| 弱承接 | 仅时间顺序相连，无逻辑关联 | P3 建议补一句呼应 |
| 断裂 | 读者无法判断两场的关系 | P2 |

**检查方法**：只看每场的第一段和最后一段，串联朗读。若串不起来，即为衔接问题。这是长篇审校中最省时高效的检查法。

## 3. 情节转折的铺垫要求

一个转折要成立，需要三种前置之一（至少一种，两种更好）：

1. **信息前置**：读者/角色提前获得了使转折可信的信息（可以很隐蔽）。
2. **性格前置**：该人物的性格使这一手"意外但合理"。
3. **结构前置**：同类事件此前发生过（哪怕是缩小版），建立了可能性。

三种全无 → 转折为"硬转"，记 P2；若该转折承载主线高潮 → P1。

**反向检查**：铺垫过重（读者提前猜到）不是逻辑错误，但可记 P4 并提示"悬念泄露"。

## 4. 伏笔状态机

### 4.1 状态定义

| 状态 | 含义 | 判定依据 |
|---|---|---|
| PENDING_PLACEMENT | 已规划但尚未落笔 | 仅见于大纲/设定 |
| PLANTED | 已在正文出现，尚未强化 | 有首次出现处 |
| REINFORCED | 已二次以上提及或强化 | 有至少两次出现 |
| PENDING_PAYOFF | 已建立并明确指向未来回收 | 有指向性表述（"总有一天"） |
| PAID_OFF | 已回收 | 有回收场景 |
| DEPRECATED | 已废弃 | 作者明确废止或长期未用 |
| TO_CONFIRM | 作者尚未确认 | 状态不明 |

### 4.2 合法流转

```
PENDING_PLACEMENT → PLANTED → REINFORCED → PENDING_PAYOFF → PAID_OFF
                        ↘ DEPRECATED
任意状态 → TO_CONFIRM（信息不足时）
```

**禁止的流转**：
- PLANTED → PAID_OFF（跳过强化，回收会显得突然）——除非回收场景本身解释充分。
- DEPRECATED → PAID_OFF（使用已废弃伏笔）。
- 无 PLANTED 直接 PAID_OFF = 无因回收，记 P1/P2。

### 4.3 伏笔台账

| ID | 内容 | 类型 | 状态 | 首次出现 | 强化处 | 指向 | 回收处 | 备注 |
|---|---|---|---|---|---|---|---|---|
| FS-001 | 半枚铜符 | 物件 | REINFORCED | 第2章 | 第6、9章 | 身世 | — | 待回收 |

**类型分类**（不同类型回收要求不同）：

| 类型 | 例子 | 回收要求 |
|---|---|---|
| 物件 | 信物、武器、钥匙、伤疤 | 必须有实体出场与功能实现 |
| 信息 | 一句不知谁说的话、一段记载 | 必须在后文被验证或推翻 |
| 能力 | 尚未觉醒的力量 | 必须有触发条件与代价 |
| 关系 | 一句承诺、一个未解的恩怨 | 必须有兑现或破裂的场景 |
| 规则 | 一条被提到的禁忌 | 必须有违反或遵守的后果 |
| 意象 | 反复出现的画面/气味 | 可仅作情绪回收，不必解释 |

## 5. 五类伏笔问题

### 5.1 无因回收（最严重）
回收时出现读者从未见过的元素。

- 判据：该元素在回收前是否出现过至少一次？无 → 问题。
- 定级：P1。

### 5.2 遗忘伏笔
铺设后长期无后续，且故事已结束。

- 判据：伏笔状态停留 PLANTED/REINFORCED，且已过结局。
- 定级：P2（若该伏笔指向核心谜题 → P1）。

### 5.3 突然回收
从 PLANTED 直接跳到 PAID_OFF，回收场景缺少准备。

- 判据：回收前两章内是否有任何提醒？无 → 读者会感到突兀。
- 修复：在回收前 1–3 章插入一次轻量提醒（不影响情节）。

### 5.4 回收过度解释
回收时把前文所有细节逐一解释，破坏回味。

- 这通常不是逻辑错误，记 P4 并提示。

### 5.5 伏笔冲突
两条伏笔的回收互相矛盾（如 A 说父亲死于火灾，B 的回收显示父亲死于刀伤）。

- 判据：把两条回收并排放，是否指向两个不同事实？
- 定级：P1。

## 7. 输出模板示例

```
### 问题编号：FORESHADOW-002
- 问题标题：铜符的回收缺少任何前置功能说明
- 问题等级：P1
- 问题状态：待确认
- 所属审校模块：M07 情节衔接与伏笔
- 发生位置：第 34 章「开门」第 4 段
- 问题描述：主角用半枚铜符打开宫门机关，但此前铜符仅作为身份信物出现，
  从未提及它有开启机关的功能，也无任何暗示（如纹路特殊、与锁孔吻合）。
- 原文证据：第34章：「他把半枚铜符按进凹槽，机括轻响。」（TEXTUAL）
  第2章：「母亲留下的半枚铜符，他一直贴身收着。」（TEXTUAL）
  第6、9章：仅用于表明身世（TEXTUAL）
- 冲突基准：FS-001 状态为 REINFORCED，功能域为"身份信物"（TEXTUAL，第6、9章）
- 问题原因：无因回收——回收所需的功能属性未在任何前置文本中建立，
  伏笔从"身世象征"直接扩展为"机关钥匙"，跨了功能域。
- 影响范围：第34章开门方式；第36章"铜符被夺"的危机强度；第38章回收另一枚
  铜符的意义（若另一枚也有同样功能，则第34章的稀缺性被削弱）。
- 最小修复方案：在第9章补一句观察细节（"符背的纹路和城门旧锁上的花纹一样"），
  使功能属性提前建立，不改变任何情节。
- 替代方案：第34章改为铜符仅证明身份、由守门人主动开门，牺牲"机关"的爽感
  但逻辑最稳。
- 修复后复审要求：确认 FS-001 台账功能域已更新；确认第38章另一枚铜符的处理
  与新设定不冲突；确认第2、6、9章表述无需连带修改。
```
