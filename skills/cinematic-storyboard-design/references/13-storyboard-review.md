# 13 分镜审查：问题分级与修改建议

审查不是重做，是**定位问题并给出可执行的修改路径**。审查者不替代导演做决定，但必须把代价说清。

## 13.1 审查的六个维度

| 维度 | 核心问题 | 判定依据 |
| --- | --- | --- |
| 叙事 | 镜头是否服务剧情 | 每镜有功能，功能无重复无缺失 |
| 清晰 | 观众是否看得懂 | 空间、人物、因果可辨 |
| 节奏 | 是否有起伏 | 有顿点、有加速、无平推 |
| 视觉 | 是否有统一主张 | 与视觉方案一致 |
| 连续性 | 是否穿帮 | 十项清单 |
| 可执行 | 是否拍得出来 | 无物理不可能、无成本失控 |

## 13.2 问题分级

| 等级 | 定义 | 必须处理 | 示例 |
| --- | --- | --- | --- |
| P0 | 穿帮或叙事断裂，观众必然出错 | 是，交付前清零 | 越轴、道具消失、人物凭空移动、关键信息缺失 |
| P1 | 明显削弱效果，多数观众会感到不对 | 建议处理，需用户确认 | 景别单调、转折点无镜头、运镜无动机 |
| P2 | 专业视角可见，普通观众不觉 | 记录，可延后 | 构图为对称性略偏、光比不够统一 |
| P3 | 优化建议 | 可选 | 某镜可换更经济的机位 |

## 13.3 常见问题清单

### 叙事类

| 问题 | 表现 | 修改方向 |
| --- | --- | --- |
| 镜头无功能 | 删掉不影响理解 | 删或合并 |
| 功能重复 | 三个镜头都在说"她很紧张" | 保留最强的一个 |
| 关键信息缺失 | 观众不知道门是谁开的 | 补一个信息镜 |
| 信息给太早 | 悬念提前泄露 | 调整揭示顺序，标 `[建议]` |
| 情绪无落点 | 台词说完就切走 | 加 1–2 秒反应镜 |

### 视觉类

| 问题 | 表现 | 修改方向 |
| --- | --- | --- |
| 景别单调 | 连续 5 个中景 | 在转折处跳变 |
| 机位无立场 | 全是平视正面 | 关键台词给越常规机位 |
| 构图无关系 | 两人并排站，看不出亲疏 | 用距离/遮挡/光影重建关系 |
| 运镜炫技 | 每个镜头都在动 | 删至 ≤30% |
| 光无来源 | "柔和的氛围光" | 指定实景光源 |
| 风格不一 | 上一场冷调下一场暖调无理由 | 回到视觉方案统一 |

### 技术类

| 问题 | 表现 | 修改方向 |
| --- | --- | --- |
| 越轴 | 正反打分处两侧 | 插中性镜过渡 |
| 视线错 | 高度/方向不匹配 | 重算机位高度与朝向 |
| 动作断 | 前一镜抬手，后一镜已放下 | 改为动作接或补中间镜 |
| 银幕方向反 | 追逃方向相反 | 统一方向 |
| 时长不可行 | 3 秒内完成 5 个动作 | 拆分或延长 |

## 13.4 审查流程

```
1. 通读镜头表，不看描述，只看功能列 → 判断叙事是否成立
2. 读描述，在脑内"放映" → 记录看不懂的地方
3. 逐场核十项连续性 → 建冲突表
4. 跑 shotlist_lint.py → 机械问题
5. 按分级汇总 → 出问题清单
6. 每条给修改建议（≥1 个具体方案）
```

**第二步最关键**：脑内放映时"卡住"的地方，就是观众会卡住的地方。

## 13.5 问题记录格式

```markdown
| 编号 | 等级 | 位置 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- | --- | --- |
| R-01 | P0 | SC03-SH07→SH09 | 苏瑾持伞手由右换左 | 穿帮 | SH09 改右手；或在 SH08 加换手动作 |
| R-02 | P1 | SC05 全場 | 12 个镜头中 9 个中景 | 平、无重点 | SH04 改全景建立；SH09 改近景强调 |
| R-03 | P2 | SC07-SH03 | 主光方向与前镜相反 | 细看可见 | 统一为窗光从左 |
```

## 13.6 修改建议的写法

好的建议包含三件事：**改哪里 + 怎么改 + 代价**。

| ✗ 无效建议 | ✓ 有效建议 |
| --- | --- |
| 这场节奏太慢 | 建议把 SH05–SH08 四个反应镜合并为两个（删 SH06、SH08），本场缩短约 8 秒，代价是失去陈默的第二次犹豫 |
| 构图不好 | 建议改为过肩构图，前景放陈默虚焦肩部占左侧 1/4，可强化"她在被审视"，代价是需要多一个机位 |
| 加点气氛 | 建议在 SH03 增加窗外雨声渐强，与 SH12 的咳嗽形成声音对比，无额外成本 |

## 13.7 审查报告结构

1. 审查范围与依据（哪几场，对比哪版视觉方案）
2. 总体判断（可用 / 需修改 / 需重做）——一句话结论
3. 问题统计（P0/P1/P2/P3 各几条）
4. P0 问题详表（必须解决）
5. P1 问题详表（建议解决，附取舍）
6. P2/P3 汇总（可作为下一版优化）
7. 亮点（值得保留的设计，审查不只是挑错）
8. 修改后的影响预估（时长变化、镜头增减、成本影响）

## 13.8 审查者的边界

| 可以做 | 不可以做 |
| --- | --- |
| 指出问题与代价 | 直接改写别人的镜头设计并当作定稿 |
| 给多个替代方案 | 只给一个方案并要求接受 |
| 判断是否符合视觉方案 | 推翻视觉方案本身（除非用户要求） |
| 标注不确定处 | 用"个人喜好"当专业判断 |

## 13.9 自检

- [ ] 每条问题有等级、位置、影响、建议
